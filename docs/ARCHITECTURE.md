# Architecture

FreeAudio is a SwiftUI `MenuBarExtra(.window)` app. Layers: **Views → Services → system frameworks** (Core Audio through the macOS 15+ Swift object API, AppKit, and two private functions loaded with `dlsym`). `Core/` holds pure logic that is unit-tested; `Models/` holds plain data. There is no separate ViewModel layer.

The plan and engine design for later phases are in [ROADMAP.md](ROADMAP.md). This file describes what exists now (Phases 1–4: listing, device volume, per-app volume, robustness, software volume and volume keys).

## Layout

```
FreeAudio/
├── App/        FreeAudioApp (@main, MenuBarExtra scene), AppDelegate (owns AudioManager; single instance, launchd hand-off)
├── Core/       Pure logic, compiled into the app and into Package.swift for `swift test`: VolumeCurve, AppGrouping (+ AudioApp, ProcessRecord, AppInfo), AppSetting, DeviceSetting (+ SoftwareVolumePlan), RenderKernel, EngineDiff
├── Audio/      Core Audio layer, not @MainActor: CoreAudio+Extensions (addresses, typed property access, PropertyListener), PrivateAPI (responsibility, TCC), HALQueue, TapEngine (+ RealtimeState and the C IOProc)
├── Models/     AudioDevice
├── Services/   @MainActor singletons (`static let shared`), plus AudioManager owned by AppDelegate
└── Views/      MenuBarView (root), OutputDeviceSection, AppListSection
Tests/FreeAudioCoreTests/   Swift Testing (run with ./scripts/test.sh)
Spikes/TapLab/              Probe app for the roadmap spikes (not part of the app build)
```

The Xcode project is generated by XcodeGen from `project.yml`; every `.swift` file under `FreeAudio/` is included automatically. `scripts/build-app-clt.sh` builds without Xcode.

## Services

| Service | Responsibility |
|---|---|
| `AudioManager` | Owned by `AppDelegate`. Starts the services and binds `DeviceVolumeService` to the default output; `diagnostics()` backs `FreeAudio --dump-audio` |
| `DeviceService` | Output devices (hidden devices and FreeAudio's own `com.freeaudio.agg.` aggregates filtered out), default output, switching it (alert sounds follow when they followed the old default). Device-list and default-output listeners, coalesced 50 ms |
| `DeviceVolumeService` | Volume and mute of the default output. Hardware tier: `VirtualMainVolume` and `Mute` with listeners (falls back to per-channel notifications), Bluetooth re-read after 400 ms. Software tier (no settable volume, or "Use Software Volume"): volume and mute stored per device UID in `devices.json`, applied by `TapService`'s rest engine; `step(by:)` for the volume keys |
| `AppAudioService` | Reads Core Audio process objects, groups them with `AppGrouping`, publishes the apps playing output (`kAudioProcessPropertyIsRunningOutput`) with a 3 s row grace. Process-list listener, per-process `IsRunningOutput` listeners, and a poll (1 s with the panel open, 5 s closed) as the backstop. Caches app icons |
| `TapService` | Desired-state reconciler: computes one `EngineSpec` per app with non-default settings (running apps by process objects + followed bundle IDs; saved apps that aren't running get a pre-armed bundle-ID tap), diffs it against the running engines (`EngineDiff`) and applies create / replace (new before old) / in-place process update / gain-only / destroy (fade first) on `HALQueue`. Watchdog restarts silent engines' IO so the Mac can sleep. Failure backoff, stuck state, `restartAll`, synchronous `shutdown` on quit |
| `PermissionService` | System Audio Recording status via `TCCAccessPreflight`; asks (`TCCAccessRequest`) the first time a tap is needed; deep link to the Privacy pane |
| `VolumeKeyService` | Session event tap for the volume keys (`NX_SYSDEFINED`); consumes a key only when its handler (set by `AudioManager`) handles it: while the default output uses software volume. Needs Accessibility; started once a software-volume output is in use, recreated after wake |
| `VolumeHUDService` | FreeAudio's volume HUD: a non-activating panel at the top right of the menu bar screen (the system HUD can't be triggered, OSDUIHelper draws the old centered OSD) |
| `SettingsService` | UserDefaults (`fa.` keys), JSON helpers, versioned migration stub, per-app settings in `apps.json` (500 ms debounced save, flush on quit, unreadable file moved to `apps.backup.json`); also hosts `AppLanguage`, `LanguageStore` and `L(_:_:)` |
| `LaunchService` | Launch at login via a per-user launchd agent in `~/Library/LaunchAgents` (with crash restart) |
| `UpdateService` | Checks GitHub Releases for a newer version |
| `CGHelpers` | `runWithTimeout` for blocking system calls |

## Key flows

```
Launch:    AppDelegate.init → SettingsService.migrateLegacyDefaults → AudioManager()
           applicationDidFinishLaunching → single-instance check (a launchd instance waits for
           the replaced one to quit) → LaunchService.prepareAtLaunch → AudioManager.start
           → DeviceService.start, AppAudioService.start, default output → DeviceVolumeService.bind

Device change: HAL listener (devices / default output) → DeviceService.refresh (50 ms coalesce)
           → @Published outputDevices / defaultOutputUID → AudioManager → DeviceVolumeService.bind

App list:  process-list or IsRunningOutput listener (100 ms coalesce), or the poll
           → AppAudioService.refresh → ProcessRecords → AppGrouping.group → apps (3 s grace)

Per-app volume: slider → SettingsService.updateAppSetting → TapService.reconcile
           → EngineDiff → setGain (atomic write, no HAL work) or create/replace on HALQueue
           → TapEngine.start: tap (bundleIDs + processRestoreEnabled, mutedWhenTapped or muted)
             → private stacked aggregate on the app's output device → C IOProc → AudioDeviceStart
           IOProc: RenderKernel (buffer mapping, 30 ms ramp, output gate, soft limiter)

Software volume: default output without hardware volume and below 100% → rest engine
           (exclusion tap scoped to the device: everything except FreeAudio and the controlled
           apps, by process object and bundle ID) at the device gain; app engines on that device
           get app gain × device gain. A change in the controlled set replaces the rest engine:
           new rest + new app engines start silent and cross over with the outgoing ones at one
           host time. Back at 100% for 2 s → rest engine stopped without a fade

Device events: default output change → app refresh + reconcile (apps still on the old default
           follow for 3 s); sample-rate change → engines on that device rebuilt (crossfade);
           coreaudiod restart → listeners re-registered, engines rebuilt; wake → rebuilt

Engine idle: watchdog sees ≥3 s of silence → AudioDeviceStop + Start → IO waits for audio
           (releases coreaudiod's sleep assertion); TapAutoStart resumes it

Grouping:  per process: its own top-level .app → (bundled processes) the responsible app
           → the outermost .app containing its executable → its own row (plain executables
           such as afplay are not attributed to the terminal that launched them)
```

Per-app settings will be keyed by `AudioApp.id` (bundle ID, or `exec:<name>`), per-device settings by device UID; never by PID or `AudioObjectID` (Core Audio reuses object IDs).

## Localization

UI strings are inline Turkish/English pairs: `L("Ayarlar", "Settings")`. `LanguageStore` is a hand-written `Observable`, so any view that calls `L` re-renders when the language changes. The choice is stored under `fa.language` (default: Turkish). Code, comments and docs are in English.

## High-risk files

| File | Why |
|---|---|
| `Audio/CoreAudio+Extensions.swift` | `PropertyListener` underpins every live update; listener blocks run on the main queue |
| `Core/AppGrouping.swift` | Decides which row a process belongs to; covered by `AppGroupingTests`, but check new app types with `--dump-audio` |
| `Services/AppAudioService.swift` | Polls Core Audio every 1–5 s; keep the refresh cheap |
| `Audio/TapEngine.swift` | Real-time code: the IOProc must not allocate, lock, log or touch ARC objects; `stop()` before releasing an engine |
| `Services/TapService.swift` | Decides which apps are tapped; a wrong spec silences or doubles an app. Test with real playback |
| `Views/MenuBarView.swift` | Root container; check panel sizing on macOS 27 (it sizes to the content's minimum size) |
